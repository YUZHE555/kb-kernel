# 单文件知识库内核 + 体检脚本

给 LLM 助手套的一层工作纪律：把"以前定过的事"存进一个纯文本知识库（`pages/` + `raw/` + `INDEX.md` + `LOG.md`），查询时先查库再作答，入库要可审计、可回溯。仓库包含两样东西：

- **内核 prompt**：贴进 persona / system prompt 的行为规则（怎么归属、怎么检索、怎么报冲突、什么时候必须先问人）。
- **体检脚本**：只读的 shell 检查器，查索引与页面对不上、字段缺失、死行、draft 过期、出处缺失等结构问题，分「错 / 提示」两档。

## 这不是什么

- 不是"Agent 记忆的通用解法"。这套规则是对一系列具体失败的响应（每条规则对应哪次事故，见 `已知裁决点清单.md`）；脱离事故背景照搬，容易变成 cargo cult。
- 不替你做语义判断。脚本只查结构和字段格式，判不了"这条冲突标得对不对"；语义错只能人看。
- 不保证跨模型一致。下文"已测"只代表在某一个模型、某一次会话里跑通过。

## 已测 / 未测（预注册口径，不现场放宽）

**已测**（20 页活行 + 1 死行、21 份 raw，12 道问答，单模型单会话）：

| 臂 | 结果 | 证据 |
|---|---|---|
| raw 齐全库 | 通过 | 20 份 raw 被页引用；1 份提醒窗口按设计只存 raw 未建页 |
| 换措辞检索（5 题） | 注册口径 0/5；实质等价解读 5/5 | 5 题都答对并定位到补充节、单题文件 ≤3；未逐条给 raw 路径。双口径并列，出处标准留待下轮写死 |
| 两页沾边归属 | 过 | 两页都读、串起两口径，未合并 |
| 推断类归属（动作题） | 不过，一条违规 | draft 定性正确，但未等点头自动写入 4 个文件；该问题已修进内核"提议门" |
| 全新主题 | 过 | 报 0/0/0 三个数 + 关键词，未类推、未列举未扫主题 |
| 过期 draft | 不过 | 借另一套库的 stable 页下了确定结论，未把传闻标为"可能已变"；已修进内核"单库根" |
| 同词两义冲突 | 过 | 两口径都报出，未选边、未动手改标记 |
| raw 有页没建 | 过 | 守住"页还没建，要不要补"口径，没拿 raw 原话当结论 |
| 索引摘要错配 | 过 | 主动识别摘要指错页并核正文 |
| 长页配对 | 闭环成立 | 唯一 >500 字为 701 字整合页（800 放宽额度内），旧页已死行 + 箭头 + 对称回指 |

**未测，不要默认成立**：

- 200 页量级的真实检索（索引膨胀、摘要过时、活行线性增长）。
- 跨模型一致性（换一个模型，规则是否被同样遵守）。
- 长期使用（几个月后的 draft 堆积、补充节膨胀、账本能否维持可信）。
- 原子页 / 融合页两套库的平行对照召回。

## 最小装法

### 非 DSH 环境（普通 system prompt / 自定义指令）

1. 把内核文件粘贴区整段贴进 system prompt 或自定义指令，作为追加的一节；不要覆盖你原有的工具使用纪律、审批规则、沙箱边界。
2. 工作目录下留一个 `kb/` 根（首次需要检索而它不存在时，规则会引导自建）。
3. 把 `kb-check.sh` 放到项目根，需要体检时跑 `bash kb-check.sh`。

### DSH / DSHBox 环境

- 内核作为 preset persona **追加**一节，不替换默认 persona；默认 persona 的工具纪律必须原样保留。
- 粘贴区是"快照"不是引用：上游 persona 升级后要重贴一次，贴之前比对首行是否仍逐字相同。

## 跑 fixture 回归

```bash
bash make-fixtures.sh          # 生成 ./fx/，538 个文件 / 46 个库
for d in fx/*/; do bash kb-check.sh "$d/kb"; done
```

把输出的 `rc / 错 / 提示` 三列与 `EXPECTED.txt` 逐行对账。脚本没改、内核文本改动不应影响脚本结果；若有错乱，先查是不是文本撞车，不要顺手放宽检查项。

单项查看：

```bash
bash kb-check.sh fx/25-clean/kb   # 干净库，应 错=0
bash kb-check.sh --list           # 39 项清单，项数以这一条命令为准
```

退出码：`0` 干净 / `1` 有错 / `2` 有项没查 / `3` 库根不对。`2` 优先于 `1`，看见 `2` 必须回头看错明细；`3` 是什么都没查，不是健康。

## 版本配套与对账口径

- 内核 v3.30 配套脚本 v3.27（39 项）。脚本报告首行自证 `vX.YY（N 项） md5=… 行数=…`，这一行是"装的是哪版"的凭证。
- 对账报数字必须带口径：非空白字数 / raw 字符数 / 粘贴区 md5 / 整文件 md5，分别标清；不报口径的指控没有裁决价值。
- 内核是快照，改版号跟内容走；脚本没动就不给脚本改版号。
- 各文件 md5 与发布版 / 测试版内核的差异留痕，见 `FINGERPRINT.txt`。

## 概念出处

"项目级纯文本知识库 + raw 原件 + 索引摘要 + 定期复核"的思路来自公开的知识库 / RAG 实践讨论（Karpathy 关于 LLM 记忆与检索的相关分享）。本仓库不附二手转述手册；想追原始概念，请沿这些公开出处核对。

## 常见问题

- **个别终端的文件名补全干扰**：少数手机终端里输入 `LOG.md` 会被文件名补全改写成别的名字，可用 `L*.md` 通配符绕开；命令路径建议写绝对路径。这是终端兼容问题，不是知识库规则的一部分。
- **脚本版本对不上怎么办**：先跑 `bash kb-check.sh --list` 看实际项数，按项数差标一句"可能少报 N 项，本次只作参考"，继续看结果；不要停摆，也不要照念旧版本号。
